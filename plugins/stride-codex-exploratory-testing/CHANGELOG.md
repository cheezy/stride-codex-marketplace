## [0.3.1] - 2026-11-08

### Fixed

- **The explorer's write rule no longer contradicts its cleanup rule** (W2675). This resolves the first of 0.3.0's *Known issues*. The last sentence of the tools paragraph in `agents/explorer.md` said the report was the one file the explorer could ever write, which, read literally, ruled out the scratch files the cleanup rule puts in a single `mktemp -d` directory. It now says the report is the only file written outside that scratch directory, and that the report never goes inside it. The report is still written with one `shell` command under the one-path rule, and the ban on edit, write and patch tools is unchanged. Both structure suites pin the new sentence under the existing label and gain one check, with the same label in bash and PowerShell, that fails if the old sentence comes back. Each suite now runs 205 checks.

### Not verified in a live Codex CLI

- **Nothing in this release has been run in a live Codex CLI session.** The changed sentence in `agents/explorer.md` was checked by the two structure suites; no explorer was dispatched, and the manual live checks planned for this release (W2677) were not run.

### Known issues

- **The installers overwrite an existing `AGENTS.md`.** With `--project` (`-Project` for `install.ps1`), `install.sh` and `install.ps1` copy this plugin's `AGENTS.md` over the `AGENTS.md` in the project's root; without it they copy it over `~/.agents/AGENTS.md` (`$env:USERPROFILE\.agents\AGENTS.md` for `install.ps1`). Neither asks first or keeps the file it replaces. `stride-codex-security-review`'s installers write the same two paths, so installing the second of the two plugins replaces the first one's `AGENTS.md`, and either plugin's project install replaces a project's own `AGENTS.md`. The installers are unchanged since 0.3.0, and this is not fixed in 0.3.1.
- The second of 0.3.0's *Known issues* is still open: `install.sh` copies the two agents as Markdown into `~/.agents/agents/`, while Codex describes custom agents as TOML files under `.codex/agents/`, and no live install has checked whether Codex picks them up.

## [0.3.0] - 2026-11-04

The G449-G451 batch from the Claude Code plugin, carried over to Codex CLI in this edition's own words. Most of it lands in the `explorer` agent: an inline rules card, output contract `1.0`, a curl-only way of observing HTTP with a `no_observation_surface` ending, a safety boundary built from two required lines, an optional report file with a short summary reply, a verify mode and a rule for reading files in ranges. The harden skill can now run without asking questions, and the descriptions Codex loads in every session are shorter, with two long skill sections moved into per-skill `references/` files.

One release covers the whole port. The nine commits since 0.2.0 are W2624 (the card, `30ffa11`), W2625 (contract `1.0`, `a1ac427`), W2626 (HTTP observation, `0ae712d`), W2627 (the safety boundary, `1c384cb`), W2628 (the report file, `dd085d2`), W2629 (verify mode, `ebafbcc`), W2630 (unattended harden, `241b88b`), W2631 (ranged reads, `2bec5b9`) and W2632 (descriptions and references, `bee32d3`). The explorer's tools line is still `read`, `search`, `glob` and `shell`, and both structure suites now run 204 checks each, with identical labels in bash and PowerShell. A figure given inside a bullet below is the value at that step. None of it has been run through a dispatched Codex session: the CLI is not installed where the port was done.

**Anything that dispatches `explorer` itself must change, or its sessions end blocked.** The environment context now needs `AUTHORIZED_NON_PRODUCTION: yes` and an `ALLOWED_HOSTS` line, each on a line of its own; a session missing either sends no probe and returns `blocked`, and a verify dispatch returns `not_verified`. `stride-codex`'s Step 6.5 sends neither line today. That step must also pass `EXPLORATORY_REPORT_PATH` if it wants the short summary instead of the full fenced JSON, and its test of whether a manual test can be dispatched must name the tools the explorer itself holds (`read`, `search`, `glob`, `shell`), not the main loop's. Its Step 6.6 should hand the harden skill the persisted report path and an explicit `--framework`, so that run asks nothing. Verify mode and the test-account pointer are opt-in, and the contract version is unchanged at `"1.0"`.

### Added

- **`fixtures/example-explorer-output.json`**, a full contract `1.0` report built from synthetic data only, and an *Explorer output contract* section in both structure suites that checks it against the agent file's own tables (root keys, `bugs` fields, the *Status from `stop_reason`* table, the severity tokens). The section also takes passing and refused variants of the fixture; setting `EXPLORER_OUTPUT` to a report's path checks a real report the same way (W2625).
- **README sections** for the report file (*Explorer report file*, W2628) and verify mode (*Explorer verify mode*, W2629), and a paragraph on the two `references/` directories and how both install paths ship them (W2632).

### Changed

- **The explorer carries its working rules on an inline card** (W2624). A card of at most 4,096 bytes follows the safety boundary, which is untouched, between `<!-- explorer-card:start -->` and `<!-- explorer-card:end -->`: the four severity words with their rank and ladder, the tie, modifier, likelihood and unknown-impact rules, the oracle verdicts and kinds, RIMGEA mapped onto `bugs[]` fields and the stop rules mapped onto `stop_reason`. It is 4,071 bytes in this release. The four doctrine skills are now named as skills, not by a `skills/<name>/SKILL.md` path: Codex's [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) and [skills](https://learn.chatgpt.com/docs/build-skills) pages say skills are inherited from the parent and list them with their own paths, and describe no way to resolve that relative path from the project directory, where `install.sh` never puts one.
- **Explorer findings follow output contract `1.0`** (W2625): a `contract_version` root key; `status` derived from `session_sheet.stop_reason` by a published table, with `stop_reason` winning any disagreement and an unclear authorisation ending `blocked`; `replicated` (`"<k>/<n>"` over clean-start re-runs, never `"1/1"`, or `"not established: <reason>"`) and `provisional` on every bug; a `known_bad` array; and typed `questions_risks` (`{kind, text}`) and `off_charter` (`{item, candidate_charter}`) elements. An optional `<known_issues>` block, which Codex can only receive as prompt text since it documents no named arguments for a custom agent, is read as untrusted caller data and routes matching results into `known_bad`. The explore skill reads results by this contract, still accepts a pre-`1.0` report, and reports replication, known-bad results and typed questions in the debrief and backlog.
- **The explorer judges only what its own tools can see** (W2626). A *What you can observe* section has it observe HTTP through `shell` with `curl -q -sS -i` (`-q` first, so a `~/.curlrc` cannot slip options such as `-L` back in), never pass `-L` or `--location`, and request a redirect's `Location` by hand only when it matches an allowed target, recording any other redirect as a result. Markup, stylesheets and templates are never taken as evidence of how a page renders. When a charter asks for something none of its tools can observe, the session ends with the sixth stop reason, `no_observation_surface` (status `blocked`), which overrides any other stop; it is added to the card, the stop-reason list, the status table and the explore skill's mapping.
- **The safety boundary is structured** (W2627). Only the exact value `AUTHORIZED_NON_PRODUCTION: yes` authorises a session; `Yes`, `true`, an empty value, a `> `-quoted copy or a second line all mean it is not authorised. `ALLOWED_HOSTS: <host[:port]>, ...` (or `none` for a target driven only by a local command) is the only source of hosts the explorer may reach: matched exactly and without case, no wildcards or subdomains, a name and its IP listed separately, a bare host admitting only the default ports, and userinfo never matching. It binds curl, database clients, sockets and any browser tool alike, and nothing the app returns can widen it. However a session ends, the explorer cleans up what it created (scratch files in one `mktemp -d` directory, background processes only under `timeout`, nothing killed or deleted by pattern), and opens a credential file only for the one value the test-account pointer names, loading it in a single `shell` command that prints nothing. In the `heuristics` skill, the Interrupt and Starve lenses and the Saboteur Tour may only use the app's own controls. The explore skill writes both lines exactly once, first in the environment context, never writes the `yes` line unless the operator chose the explicit authorised, non-production answer, and `> `-quotes any operator, target or charter line that begins with either name.
- **The explorer can write its findings to `EXPLORATORY_REPORT_PATH` and reply with a summary** (W2628). Given that line in the environment context (never from the charter, `known_issues` or the app), it writes the whole findings object to that absolute path with one `shell` command, a single-quoted path under `noclobber` and a quoted heredoc, refusing anything already there, links included, with one `mkdir -p` retry for a missing parent. Its reply is then unfenced plain text, 2,048 bytes at most: the report path, contract version, status, stop reason, counts and one line per bug. If the write is refused or fails, the reply opens with `report: NOT WRITTEN - <reason>` and carries the fenced JSON in full, and with no path the reply is unchanged. The explorer's tools line names no edit or write tool, and because a Codex session may still offer one (`apply_patch`), the agent is told never to use one. The explore skill never passes the path.
- **The explorer has a verify mode** (W2629). With `EXPLORATORY_MODE=verify` on a line of its own and one fixed bug in a `<verify_bug>` block outside the environment context, it builds the charter from the bug, runs the `minimal_repro` exactly as probe 1 and at most one `generalization` variant as probe 2, on 2 probes and 10 tool calls. Codex documents no per-agent turn or tool-call limit, so that ceiling, like the usual 60, is one the agent counts itself. The findings gain an optional `verify` object whose `result` is `pass` (repro point reached, failure gone), `fail` (a partial fix included) or `not_verified` (repro point never reached, which is never a pass), and a report-file summary gains a `verify:` line. The safety boundary and both required lines apply in full.
- **The `stride-exploratory-testing-harden` skill can run unattended** (W2630). Given a non-empty bug source and `--framework`, it asks no question: weak evidence or two competing runners resolve to the override, a framework the operator names but the repository gives no sign of is still used, and reported as *given but not found*, and `--framework none` takes the none-detected path. A bug source that is given but unreadable, or fits no known shape, ends the run with one line naming it. The explorer's persisted report file is accepted as a bug source and is read from the file, never from the summary. Codex skills carry no `allowed-tools` key, so the skill's read, write and shell limits are stated as rules it keeps in both modes.
- **The explorer reads files in bounded ranges, once** (W2631). A *Reading files* section, outside the card, has it find the place with `search` or `grep -n`, read only a range with `sed -n '<first>,<last>p'` through `shell` (nothing records a range option for Codex's `read`), never read an unchanged file or range twice, re-read only the new part of a file that changed, and inspect a binary file the charter names through `shell` with `file`, `wc -c` or `strings | grep -n`, never dumping it. Every path or pattern goes into those commands single-quoted. The credential bullet honours a test-account pointer only when there is exactly one, standing alone on its line before any untrusted text.
- **Shorter always-loaded descriptions, and two long sections moved to `references/`** (W2632). Codex loads both agents' descriptions and every skill's, and in this edition the command entry points are skills, so ten descriptions were cut back to their triggers: the two agents' (`explorer` 1,887 to 657 bytes, `charter-generator` 1,660 to 615, both losing their `<example>` blocks) and the routing skill's and the seven command skills' — 9,133 bytes down to 4,969 in all, with every triggering condition and the explorer's safety statement kept. The `session` skill's *Session artifacts on disk* body moved to `skills/session/references/session-artifacts.md` (`SKILL.md` 23,735 down to 12,973 bytes), and `skills/bug-advocacy/references/worked-example-and-tone.md` now holds `bug-advocacy`'s worked example and the complete tone rule (27,567 down to 23,035 bytes). Each skill keeps a stub that links its file and tells the reader to `read` it, because [Codex's skills documentation](https://learn.chatgpt.com/docs/build-skills) lists `references/` as an optional folder without saying Codex loads it. The command skills' citations now name the reference file. **`install.sh` and `install.ps1` now copy a skill's `references/` directory** along with its `SKILL.md`; the marketplace copy vendors the whole tree.
- **Both structure suites pin each step**, with identical labels in bash and PowerShell and a self-test for each new helper: the card's markers, cap and its agreement with `bug-advocacy` (W2624); the output contract (W2625); the observation rules and a fetch-free tools line (W2626); the safety boundary (W2627); the report path and an edit-tool detector (W2628); verify mode and the `verify` object (W2629); the unattended harden path (W2630); the reading rule (W2631); and the descriptions, references and installer copy (W2632). The suites go from 30 checks at 0.2.0 to 204.

### Not carried by this edition

- **W2265, W2267 and W2271** are consumer-side: they move `stride`'s exploratory step onto contract `1.0`, batch manual tests into charters, and shorten that step's text and its findings contract. This plugin has no consumer step of its own; the matching work is owed to `stride-codex`'s Steps 6.5 and 6.6.
- **The dispatch-template half of W2270**, a single template that carries both required lines, the report path and the test-account pointer, belongs to `stride-codex`'s Step 6.5. Only the explorer's reading rule is ported here.
- **W2273**'s measurements come from Claude Code transcripts alone; nothing here claims a measured saving for Codex. The byte counts above are sizes, not a measurement of cost.
- **W2263** took a web-fetch tool away from the upstream explorer. The Codex explorer has never held such a tool, so only the curl rule and the `no_observation_surface` ending came across.
- **There is no hook suite in this repository.** The stop reasons and status table a `stride-codex` consumer reads are pinned only here, so drift between the two is not checked mechanically.

**Divergence owed upstream:** `-L` and `--location` are off limits to this explorer, which only ever requests a redirect target itself, and only on an allowed host. Upstream, `-L` is still permitted when the redirect itself is what a probe tests; the OpenCode and Copilot editions are as strict as this one.

## [0.2.0] - 2026-08-02

A capability sweep ported from the Claude Code edition's 0.2.0: two corrections to existing content, a sixth doctrine skill, session artifacts that survive the conversation, and the plugin's first interactive and hardening command-skills.

### Added

- **`interfaces` lens** — the Heuristic Test Strategy Model's **I**nterfaces element joins the coverage lens in the `chartering` skill, covering APIs, imports and exports, UI surfaces, and integration points between systems: the boundaries where service-oriented and LLM tool-calling applications most often fail. **Downstream consumers must handle `interfaces` as a new allowed value of a charter object's optional `lens` field** (`agents/charter-generator.md`), alongside the existing `structure`, `function`, `data`, `platform`, `operations`, and `time`.

- **`bug-advocacy` skill** — a sixth doctrine skill encoding Cem Kaner's **RIMGEA** (Replicate, Isolate, Maximize, Generalize, Externalize, And say it clearly), the discipline for the work between "an oracle says this is wrong" and a report someone will act on. It also defines **severity**, which the explorer's contract has always required and this plugin has never defined: a four-level rubric — **Critical > High > Moderate > Minor** — with an impact ladder of explicit clauses, three aggravating-only modifiers, and an agreement test, so two sessions rating the same bug from the same evidence land on the same level. Routed from the orchestrator's routing table and handed off to from `oracles` at the point a result is classified a Defect. **The explorer's `bugs[]` entries gain `minimal_repro`, `worst_observed`, `generalization`, and `stakeholder_impact`** (Isolate / Maximize / Generalize / Externalize), which are **honest-or-"could not establish", never invented**, and the `stride-exploratory-testing-explore` command-skill carries all four through aggregation with a merge rule for cross-session duplicates. RIMGEA's Maximize step is explicitly bounded by the explorer's absolute safety boundary: a worse failure that cannot be demonstrated safely is a risk to name, never a result to claim, and security bugs are maximized by reasoning rather than by exploitation. **Downstream consumers must handle the four new `bugs[]` fields.**

- **Session artifacts that survive the conversation.** The plugin now persists three things to a small, predictable, gitignorable tree in **the project under test** (the current working directory, never the installed skill tree): `.exploratory/sessions/<timestamp>-<target-slug>.md` (one aggregated debrief per explore run), `.exploratory/backlog.md` (the charter backlog made real — charters deferred for budget, off-charter items parked mid-session, and candidate charters nobody has run yet), and `.exploratory/coverage.md` (the product coverage outline: which areas were explored, when, what is covered, and what is still dark). The convention — paths, the `date +%Y-%m-%d-%H%M` timestamp, the `[a-z0-9-]` slug rule, the per-artifact lifecycle, the first-write header rule, the `.gitignore` line, and the first-run rule — is owned by a new **Session artifacts on disk** section in the `session` skill. **A missing artifact is an empty starting state, never an error:** a first run in a new project creates the tree rather than failing. The coverage outline is deliberately a **map, not a score** — it carries no percentage, because "explored enough" is a judgment, not a number. All five command-skills participate: the explore skill writes its debrief by default (gaining `--output` to redirect it) and updates both shared files; charter, nightmare-headline and recon append the charters they generate; debrief appends parked items and refreshes coverage; recon may add an un-explored area stub but never marks an area explored, because surveying is not exploring.

- **`charter-generator` accepts an optional `coverage context`** — a digest of what has already been explored against the target and what is already on the backlog — and a new optional `deprioritized` root key in its output contract reports the charter ideas it ranked down or dropped because prior coverage shows the ground was already explored. **`deprioritized` is distinct from the existing `coverage_notes`** and does not replace it: `coverage_notes` is about SFDIPOT angles the agent chose to skip on this run; `deprioritized` is about ground a previous session already covered. **Downstream consumers must handle the new optional `deprioritized` key.** The agent remains read-only.

- **`stride-exploratory-testing-pair` — the plugin's first interactive testing mode.** Every command-skill so far is either fully generative (charter, nightmare-headline) or fully autonomous (explore, whose `explorer` agent is forbidden to ask the user a question). There has been no mode in which a **human drives the product and the assistant rides along**. The pair skill is the exact inversion of explore: the human exercises the application and reports what they did and saw; the skill suggests the next probe and **names the `heuristics` lens that generated it** (so the session stays reviewable and the tester learns the lenses), judges each reported result with `oracles`, works every confirmed defect through the `bug-advocacy` RIMGEA discipline before it reaches the `BUGS` block, and keeps the human's SBTM session sheet and off-charter parking lot so they never context-switch into note-taking. Its signature behaviour is **unprompted coverage-gap reporting**: it maintains ledgers of areas touched, the `heuristics` Variable Catalog rows, and seven fixed stances, and sweeps them on a schedule to volunteer what the session has neglected — each gap raised **at most once per session**, so a pair never becomes a scold. The session is bounded by the human's real wall-clock box, and its `DURATION` comes from two real `date` stamps — the one wall-clock figure this plugin allows an agent to report, because it is genuinely observed. It writes its sheet to `.exploratory/sessions/` (rewritten at checkpoints, so a dropped conversation costs nothing) and appends parked items to the backlog; it produces no debrief and never touches the coverage outline.

- **`stride-exploratory-testing-harden` — the first path from *Explored* back to *Checked*.** The thesis has always been **Tested = Checked + Explored**, but the two halves were only ever contrasted: a bug found by exploration stayed found, and nothing prevented its regression. This skill takes a session's **oracle-confirmed** bugs from a persisted session sheet, a debrief, an `explorer` findings object, or pasted findings, and drafts a regression check per bug **from its `minimal_repro`** — RIMGEA's Isolate step already produces the shortest set of conditions that still triggers the failure, which is exactly what a minimal test case needs. **It detects the project's test framework rather than hard-coding one** (existing test files first, confirmed against the ecosystem's manifest across nine ecosystems) and **states what it detected, and on what evidence, before anything is written**; none detected means it says so, writes nothing, and renders framework-agnostic Setup/Trigger/Assertion specs rather than guessing. Convertibility is an explicit four-part test, and a bug failing any part is **reported, never guessed at**. Every draft is labelled `NOT RUN` and carries its red-then-green acceptance in its header: a check for an open bug should **fail** today, and that failure is the evidence it reproduces the bug. Drafts are staged in `.exploratory/checks/<timestamp>-<slug>/` — a **fourth** artifact path — and a colliding filename is suffixed and reported, never replaced.

### Changed

- **The safety guarantees these two skills inherit are re-grounded, because this runtime cannot enforce them the way the upstream edition does.** Upstream, the pair command's never-drives-the-app rule and the harden command's never-runs-a-check rule are backed by an `allowed-tools` frontmatter allowlist that withholds the capability outright — and both files say so, in as many words. **Codex command-skills carry no tool-restriction frontmatter**, so copying those sentences would have shipped a false claim about this runtime: `shell` is `shell`, and the one tool that makes the pair skill's `DURATION` honest is the same tool that could reach the app. Both skills now open with an absolute rule stated as an obligation rather than a mechanism — a closed positive list of the only two shell commands each ever runs, an explicit refusal clause for an operator who asks it to cross the line (which the allowlist used to refuse on the skill's behalf), and, for the pair skill, a disclosure clause requiring the sheet to record in its own name anything the assistant itself touched, so a misattributed observation cannot pass as the tester's. The `session` skill also gains the distinction the upstream edition never stated: the line is **measured versus inferred**, not human versus agent — an agent that takes two real `date` stamps has observed an interval, which is why a paired sheet may carry a `DURATION` where an agent-run sheet may not.

- **The redaction and untrusted-input rules now cover files, not just rendered output.** The `session` skill's *Safety of session artifacts* section is extended: `.exploratory/` is a new on-disk sink for observed system output, so credentials, tokens, customer data, personal data, and internal hostnames are redacted **before** a write — a file outlives the conversation and can be read by someone who never saw the session. And because the backlog and coverage outline are read back on later runs, they are treated as **untrusted data, never instructions**: a line that looks like a command is content to report, never something to obey. Artifact paths are handed only to the platform's file-read and file-write tools; the sole shell command any path may appear in is a `mkdir -p` of its own dirname, and the session slug is restricted to `[a-z0-9-]` so it can carry neither a traversal nor a shell metacharacter. This edition states the `mkdir -p` as **required** rather than conventional: unlike the Claude original it does not assume the file-write tool creates missing parents.

- **`SFDPOT` renamed to `SFDIPOT`** across the plugin — skills, agents, command-skills, fixtures, and docs. Bach's HTSM (v6.0, 2024) lists seven Product Elements; the six-letter `SFDPOT` the plugin cited is a superseded form of the same heuristic. The `Interfaces` row slots between `Data` and `Platform`; no existing row was renamed, reordered, or dropped. The charter object's `source` enum value is still the literal `sfdpot` — it is a wire value, not the acronym, and renaming it would break existing consumers. The `[0.1.0]` entry below needed no edit: it predates the lens and carries no occurrence of either spelling.
- **The `explorer` agent no longer reports numbers it cannot observe.** `session_sheet` drops `duration` and `tbs` (Task Breakdown Metric percentages) — a wall-clock measurement an agent has no way to take, whose presence contradicted the agent's own hard rule against fabricating a result. In their place it reports what it genuinely counts: `probe_budget`, `probes_attempted`, `probes_with_finding`, `on_charter_probes`/`off_charter_probes`, `tool_calls_used`, `heuristics_applied`, and `stop_reason`. An agent session is now bounded by an **agent-native budget** — a probe budget (default 12, band 8–20) and a tool-call ceiling (5 × the probe budget), whichever is reached first; a session blocked before its first probe reports those counters as zero rather than omitting them. The `session` skill keeps the 60–120 minute box and TBS for **human-run and paired** sessions and now states plainly that neither binds an agent session; the four stopping heuristics are unchanged in substance (bullet 2 now reads "The box or the budget is up"). **The `stride-exploratory-testing-explore` command-skill gains `--probes <count>`** for the per-session probe budget; **`--timebox <minutes>` keeps its unit** and is now documented as doing only what it always effectively did — deciding how many charters run (one session ≈ 90 minutes) — and is never passed to the explorer. **Downstream consumers that read `session_sheet.duration` or `session_sheet.tbs` must switch to the counts**; the `stride-exploratory-testing-debrief` command-skill is unaffected (it consumes unstructured tagged notes). The `fixtures/` session sheet and debrief are unchanged **in substance**: both still document a **human-run** session, which keeps the box and TBS under the new split. The session sheet gains only a preamble labelling it human-run, pointing at the agent-run contract, and a worked agent-run sheet beside the human one so the new contract has an example to pattern-match against.

## [0.1.0] - 2026-07-22

Initial release of `stride-codex-exploratory-testing` — the Codex CLI edition of
the Stride exploratory-testing plugin (the "explored" half of *Tested = Checked +
Explored*).

### Added

- **Manifest & packaging** — `.codex-plugin/plugin.json` (name, version,
  description, skills), MIT `LICENSE`, `.gitignore`, and POSIX/PowerShell
  installers (`install.sh`, `install.ps1`).
- **Codex root context** — `AGENTS.md` describing the plugin for Codex CLI.
- **Five doctrine skills** — `stride-exploratory-testing` (orchestrator),
  `chartering`, `heuristics`, `oracles`, and `session`.
- **Five command-skills** (activated by name; Codex has no slash commands) —
  `stride-exploratory-testing-charter`, `stride-exploratory-testing-nightmare-headline`,
  `stride-exploratory-testing-explore`, `stride-exploratory-testing-recon`, and
  `stride-exploratory-testing-debrief`.
- **Two agents** — `charter-generator` (ranked charters from a target) and
  `explorer` (runs one time-boxed session under an absolute safety boundary).
- **Documentation** — `README.md` (install, model, skill/agent reference,
  quick-start, attribution) and `HEURISTICS.md` (pointer to the `heuristics`
  skill catalog).
- **Fixtures** — worked `fixtures/example-charters.md`,
  `fixtures/example-session-sheet.md`, and `fixtures/example-debrief.md` built on
  a synthetic target; they double as templates and regression anchors.
- **Smoke-test harness** — `lib/test-structure.{sh,ps1}`,
  `lib/test-frontmatter.{sh,ps1}`, and `lib/test-all.{sh,ps1}`: offline
  structure + frontmatter validators (no network, no jq) that gate a release.

To keep the plugin and marketplace in sync on every release, bump the version in
one place and let it propagate:

1. Bump `version` in `.codex-plugin/plugin.json` and add a new section here.
2. In `stride-codex-marketplace`, re-vendor this tree with
   `rsync -a --delete` (excluding `.git`, `.stride`, `.env`, and secret files) so
   the new `plugin.json` version moves with it.
3. Update the marketplace README Plugins-table version cell to match, then run
   the marketplace `RELEASE.md` node validator and secret scan.
4. Tag and publish both repos per their `RELEASE.md` steps.
